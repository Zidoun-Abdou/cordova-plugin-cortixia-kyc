0 Avant de commencer

Quatre choses à réunir — tout le reste est automatique.

  • Votre jeton API (format ck_live_…), visible sur votre tableau de bord Cortixia. Il porte vos packs et votre quota.
  • Un appareil réel pour tester : caméra + NFC (l'émulateur ne convient pas).
  • Pour iOS : un compte développeur Apple payant — Apple réserve le NFC aux équipes payantes.
  • Service Studio avec accès aux Extensibility Configurations de votre application mobile.
Vos écrans restent les vôtres. Le plugin n'affiche que les trois écrans de capture (cadre MRZ, attente NFC, ovale du visage). Tout le reste — parcours, résultats, marque — se construit normalement dans OutSystems.

1 Importer le plugin

Dans Service Studio : votre application mobile → module → Extensibility Configurations → collez ce JSON, puis publiez.

Extensibility Configurations
{
  "plugin": {
    "url": "https://github.com/Zidoun-Abdou/cordova-plugin-cortixia-kyc.git"
  }
}

À la publication, MABS reconstruit l'application : le plugin déclare lui-même les permissions (caméra, NFC, internet), ses écrans natifs et ses dépendances. Aucune configuration MABS supplémentaire n'est nécessaire — y compris pour les builds minifiés (règles ProGuard incluses).

L'API est disponible côté client sous cordova.plugins.cortixiaKyc dès l'événement deviceready.

2 Initialiser au démarrage

Une seule fois, au lancement de l'application — par exemple dans le OnApplicationReady, via un nœud JavaScript :

Nœud JavaScript — initialisation
// $parameters.ApiToken : votre jeton, idéalement depuis une Site Property
var kyc = cordova.plugins.cortixiaKyc;

kyc.initialize({ apiToken: $parameters.ApiToken })
  .then(function (licence) {
    // licence.quota = { limit, used, remaining }
    $parameters.CreditsRestants = licence.quota.remaining;
    $resolve();
  })
  .catch(function (e) {
    // e.message est en français, prêt à afficher
    $parameters.Erreur = e.message;
    $resolve();
  });
Le jeton n'est pas un secret d'État, mais gérez-le proprement : stockez-le dans une Site Property plutôt qu'en dur, et sachez qu'il se régénère en un clic depuis votre tableau de bord — l'ancien est révoqué immédiatement.

3 Lancer une vérification

Depuis n'importe quelle action cliente — un bouton « Vérifier mon identité » — un seul appel enchaîne les trois écrans et rend un seul résultat :

Nœud JavaScript — vérification complète
var kyc = cordova.plugins.cortixiaKyc;

// Carte d'identité : scanIdCard() · Passeport : scanPassport()
kyc.scanIdCard()
  .then(function (r) {
    if (r.status === 'success' && r.liveness.decision === 'True') {
      // Identité vérifiée — mappez vers vos variables locales :
      $parameters.Nom        = r.mrz.surname;
      $parameters.Prenoms    = r.mrz.given_names;
      $parameters.NumeroDoc  = r.mrz.document_number;
      $parameters.PhotoPuce  = r.decoded.decoded.dg2.face; // JPEG base64
      $parameters.Verifie    = true;
    } else {
      $parameters.Verifie = false;
    }
    $resolve();
  })
  .catch(function (e) {
    // L'utilisateur a annulé, ou une étape a échoué — e.code + e.message
    $parameters.Erreur = e.message;
    $parameters.Verifie = false;
    $resolve();
  });

Ce que contient le résultat

Structure du résultat (succès)
{
  "status": "success",
  "document_type": "idcard",              // ou "passport"
  "mrz": {
    "surname": "…", "given_names": "…",
    "document_number": "…",
    "birth_date": "…", "expiry_date": "…"
  },
  "decoded": {
    "decoded": {
      "dg2":  { "face": "<JPEG base64>" }, // photo officielle de la puce
      "dg11": { … }, "dg12": { … }          // champs d'identité décodés
    }
  },
  "liveness": {
    "decision": "True",                     // chaîne : "True" | "False"
    "details": { "spoof_ratio": 0 }
  }
}

Dans OutSystems, définissez une Structure reflétant ces champs et mappez la sortie du nœud JavaScript dessus. Le visage vérifié est comparé à la photo de la puce — pas à une photo fournie par l'utilisateur.

Facturation : une vérification complète consomme 3 crédits (1 par étape). Une MRZ illisible, un scan annulé : 0 crédit. Le compteur est visible en temps réel sur votre tableau de bord.

4 iOS : la signature (une seule fois)

La seule étape manuelle de toute l'intégration — Apple exige qu'elle soit faite par le titulaire du compte.

MABS signe vos builds iOS avec le profil que vous téléversez dans OutSystems. Pour que le NFC fonctionne, ce profil doit porter la capacité « NFC Tag Reading » :

  1. Sur developer.apple.com → Identifiers → votre App ID → cochez Near Field Communication Tag Reading → Save.
  2. Toujours sur le portail Apple : régénérez le profil de provisionnement de l'application (il embarque désormais la capacité NFC) et téléchargez-le.
  3. Dans OutSystems (Service Center / configuration iOS de l'app) : téléversez le nouveau profil + votre certificat, puis republiez.

Le plugin déclare le reste lui-même : l'entitlement NFC, l'identifiant de la puce des documents (A0000002471001) et les textes d'autorisation caméra/NFC.

Rappel matériel : l'antenne NFC de l'iPhone est sur le bord supérieur du dos — le document se tient en haut de l'appareil. Sur Android, elle est au centre. iOS affiche sa propre feuille système « Ready to Scan » pendant la lecture.

5 Tester

  • Générez l'application depuis Service Studio et installez-la sur un appareil réel.
  • Au lancement : l'initialisation doit remonter vos crédits restants.
  • Lancez une vérification avec une vraie carte ou un vrai passeport : cadre MRZ → document contre le dos du téléphone → visage dans l'ovale.
  • Vérifiez sur votre tableau de bord : le compteur descend de 3 crédits par parcours réussi.

✕ Si quelque chose refuse

Chaque refus porte un code stable et un message en français, prêt à afficher tel quel à l'utilisateur final. Jamais de code HTTP brut.

? Questions fréquentes

Où vont les données de mes utilisateurs ?

Les données de la puce sont décodées en mémoire côté serveur et renvoyées à votre application. Cortixia ne stocke aucune donnée d'identité.

Peut-on n'utiliser qu'une partie du parcours ?

Oui — scanMrz(), readChip() et checkLiveness() s'appellent aussi séparément (1 crédit chacun), si votre système possède déjà une partie du parcours.

Peut-on adapter l'apparence des écrans de capture ?

Les écrans autour de la capture sont déjà 100 % les vôtres. Pour les trois écrans de capture eux-mêmes (couleurs, textes, logo), une personnalisation à votre marque est possible — parlez-en avec nous.
